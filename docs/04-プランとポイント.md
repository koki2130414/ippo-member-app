# 04. プランとポイント

## プラン（`src/domain/plans.ts`）

上限は **月あたりの数値**。`0` = 使えない、`null` = 無制限。boolean のフラグは使わない。
「1on1 を月2回に」は数値の変更だけで済み、`if (plan === "personal")` のような分岐を探し回らなくてよい。

| コード | 名前 | 月額(税込) | クラス | 個別メニュー | 1on1/月 | 動画レビュー/月 | ノート/月 |
|---|---|---:|---:|:---:|---:|---:|---:|
| `light` | ライトプラン | 2,980 | 0 | 0 | 0 | 0 | 0 |
| `balance` | バランスプラン | 4,980 | 1 | 0 | 0 | 0 | 4 |
| `soccer_iq` | サッカーIQプラン | 5,480 | 3 | 0 | 0 | 0 | 4 |
| `personal` | パーソナルプラン | 6,980 | 1 | null | 1 | 2 | null |
| `professional` | プロフェッショナルプラン | 12,480 | null | null | 2 | 4 | null |

クラス動画・講義・診断は全プラン `null`（見放題）。`plans.test.ts` で上の表と定義が一致することを確かめている。

### 判定

```ts
evaluate({ plan, feature, usedThisMonth, allPlans, now }): Entitlement
cheapestPlanWith(plans, feature): Plan | null
describeEntitlement(entitlement): { title, nextStep, href }
```

| 状態 | 画面のことば（title） | 次の一歩 |
|---|---|---|
| `available` | 今月はあと◯回使えます | さっそくやってみよう |
| `no_plan` | プランに加入すると使えます | おうちの人といっしょに、プランを見てみよう → /plans |
| `not_in_plan` | サッカーノートはバランスプランから使えます | プランのちがいを見てみよう → /plans |
| `monthly_limit_reached` | 今月はここまで。来月また使えます | 10月1日（木）からまた使えるよ |

- 「今月」は JST の暦月。`usedThisMonth` は呼び出し側（サービス）が JST の月初〜翌月初で数えて渡す。
- 決済は MVP 外。プランの割り当ては運営が管理画面から行い（`members-service.ts` の `assignPlan`）、変更前後を監査ログに残す。
- 生徒側には料金表と「運営へ問い合わせる」導線だけを出す。

## ポイント（`src/domain/points.ts`）

**1行動 = 1pt。** 差は pt の大小ではなく **1日あたりの上限** でつける。pt の大小で差をつけると、「たくさんもらえる行動」だけを選ぶようになるため。

| コード | きっかけ | pt | 1日上限 | 付与する人 | 冪等キーの subject |
|---|---|---:|---:|---|---|
| `login_daily` | ログイン | 1 | 1 | system | JST 日付 |
| `profile_completed` | プロフィール記入 | 1 | 1 | system | `once` |
| `video_completed` | クラス動画を見終わる | 1 | 3 | system | videoId |
| `lecture_completed` | 講義を見終わる | 1 | 3 | system | lectureId |
| `quiz_passed` | クイズ合格 | 1 | 5 | system | lectureId |
| `diagnosis_completed` | 診断を受ける | 1 | 2 | system | attemptId |
| `streak_daily` | 連続ログイン | 1 | 1 | system | JST 日付 |
| `streak_bonus_7` | 7日続いた | 1 | 1 | system | JST 日付 |
| `class_attended` | クラスに出る | 1 | 2 | coach | sessionId |
| `reflection_submitted` | ふりかえりを書く | 1 | 2 | system | sessionId |
| `personal_menu_done` | 個別メニューをやる | 1 | 3 | system | menuItemId |
| `personal_session_done` | 1on1 を受ける | 1 | 2 | coach | personalSessionId |
| `video_review_submitted` | プレー動画を出す | 1 | 2 | system | reviewId |
| `note_submitted` | サッカーノートを出す | 1 | 3 | system | noteId |
| `coach_bonus` | コーチからの加点 | 任意(1〜100) | 無制限 | coach | `grant-{requestId}` |
| `event_participation` | イベント参加 | 任意 | 無制限 | admin | `grant-{requestId}` |
| `admin_adjustment` | 運営調整 | 任意 | 無制限 | admin | `grant-{requestId}` |

冪等キーは `buildIdempotencyKey(rule, userId, subject)` で `{rule}:{userId}:{subject}` の形に固定する。

### 付与の流れ

```
行動が成立（例: 動画を最後まで見た、をサーバーで確認）
  → points-service.awardForOwnAction（生徒本人だけ・system ルールだけ）
      → domain.decideAward（金額の妥当性）
      → store.appendPointTransaction(tx, maxPerDay)
            冪等キー重複 → already_awarded（残高は変わらない）
            今日（JST）の同ルール件数 ≥ 上限 → daily_limit_reached（「今日はここまで。また明日」）
            それ以外 → 1行追加
```

- 「行動が成立したか」は各機能のサービスが確かめる。`awardForOwnAction` を Server Action から直接呼ばせない（「見終わった」と自己申告させない）。
- 人が付与するもの（`grantPoints`）は、フォームを開いたときに作った `requestId` を冪等キーに入れる。同じフォームの二重送信は1回分になる。監査ログに残す（メモの本文は書き写さない）。

### 交換

`exchangePoints` → `store.exchangePoints`（残高確認・在庫確認・引き落とし・在庫減を1回で）。
足りないときは「あと◯ポイントで交換できます」、在庫切れは「今は在庫がありません。ほかのものをえらぶか…」。

> ポイントは現金・商品券と交換できない、有効期限の扱いなど、**資金決済法上の「前払式支払手段」に当たらない設計か**は専門家の確認が必要（README の法務チェックリスト）。

### 連続記録

`computeStreak(activeDates, today)` は `currentDays`（いまの連続）と **`totalActiveDays`（これまでの合計。減らない）** を返す。
途切れて戻ってきた日は `restartedToday` が立ち、画面では「おかえり！また今日から一歩ずつ。これまで◯日がんばってきたよ」と出す。
「失った」「リセット」「0日」といった言葉は使わない（テストで確認）。
