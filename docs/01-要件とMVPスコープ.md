# 01. 要件と MVP スコープ

## プロダクト

**IPPO** — 小学生・中学生向けオンラインサッカースクールの会員専用アプリ。
キャッチコピーは **「昨日の自分から、一歩前へ」**。

## 利用者

| ロール | できること | 見える範囲 |
|---|---|---|
| 生徒 | 動画・講義を見る、クラスに出る、ふりかえり・ノート・プレー動画を出す、診断、ポイント | 自分のものだけ |
| 保護者 | 子どもの様子を見る | **紐づけられた子どもだけ** |
| コーチ | 出欠、ノート返信、動画レビュー返信、個別メニュー作成 | **担当の生徒・担当のクラスだけ** |
| 運営 | 会員・コンテンツ・プラン・ポイント・お知らせの管理、監査ログ閲覧 | 全体（操作はすべて監査ログへ） |

## 世界観のルール（実装に落としたもの）

| ルール | 実装の場所 |
|---|---|
| ランキング・順位・他人との比較を作らない | 診断結果は「前回の自分との差」だけ（`domain/scoring.ts` の `compareWithPreviousAttempt`）。合計点も返さない |
| 連続記録は「切れたら失う」にしない | `domain/points.ts` の `computeStreak` が合計日数も返し、`describeStreak` は否定語を使わない（テストで確認） |
| 「使えません」で終わらせない。3つを言い分ける | `domain/plans.ts` の `Entitlement` が `no_plan` / `not_in_plan` / `monthly_limit_reached` を分けて返し、`describeEntitlement` が文言を一本化 |
| エラーは「何が起きたか＋次にどうするか」 | `server/services/errors.ts` の `userMessage`、`domain/schemas.ts` のバリデーション文 |
| 子ども向けの日本語・誘いの言い方 | 文言は domain に集約して、画面ごとにぶれないようにする |

## MVP に入れるもの

- 4ロールのログイン（デモモードではロール別ワンクリックログイン）
- クラス動画（アプリ内アップロード / Mux Signed Playback / YouTube 埋め込み）、講義とクイズ、サッカーIQ診断
- クラス（第n週の◯曜）と出欠・ふりかえり
- サッカーノート（写真提出→コーチ返信）、プレー動画レビュー、個別メニューと 1on1
- ポイント（取引履歴が正、冪等、日次上限）と交換
- 監査対象のチャンネル（コーチ⇔生徒・保護者、クラス全体へのお知らせ）
- お知らせ・通知、運営の管理画面、監査ログ

## MVP に入れないもの

- **決済**（プランは運営が手動で割り当てる。生徒側は料金表と問い合わせ導線だけ）
- **生徒同士の DM**（型としても作らない）
- 公開プロフィールでの本名表示、顔写真アバター（プリセットから選ぶだけ）
- ネイティブアプリ、プッシュ通知

## 判断が必要だった仕様と、いまの仮決め

仕様に書かれていない、または読み方が2通りある箇所。**セキュリティに関わるものは厳しい側に倒して確定**、それ以外は仮決めで進め、確認をお願いしたいものに「要確認」と付けている。

| # | 論点 | 仮決め | 状態 |
|---|---|---|---|
| 1 | 料金表の「クラス枠」の意味 | **月に参加できるクラス開催回数**（他の列と同じく月あたりの上限として扱う） | 要確認 |
| 2 | 「個別メニュー ○/×」 | `personalMenu` を `null`（使える）/ `0`（使えない）で表す。月の回数制限はしない | 要確認 |
| 3 | 保護者が生徒向け画面（`/points` など）を開けるか | 開ける。ただし中身は紐づいた子の分だけ（サービス層で判定） | 要確認 |
| 4 | 運営がコーチの代わりにノートへ返信してよいか | **不可**（コーチになりすました返信を作らない）。閲覧は可 | 厳しい側で確定 |
| 5 | 保護者が子の代わりにノート等を提出してよいか | **不可**（MVP） | 厳しい側で確定 |
| 6 | クラス全体チャンネルに生徒が書き込めるか | **不可**（生徒同士のやりとりの場にしない）。読むだけ | 厳しい側で確定 |
| 7 | コーチの担当範囲の決め方 | クラスから推測せず、**担当生徒を明示的な行（CoachAssignment）で持つ** | 厳しい側で確定 |
| 8 | 退会時のデータ | 本名・メール・表示名を消し、ポイント履歴・出欠・監査ログの行は残す | 要確認（保存期間を法務と決める） |
| 9 | 生年月日の保存 | 保存しない。年代（小学校低学年／高学年／中学生）だけ | 厳しい側で確定 |

## ディレクトリ構成

```
ippo-member-app/
├─ docs/                     設計メモ（このフォルダ）
├─ src/
│  ├─ domain/                純粋関数と型だけ。React / Next / Supabase を import しない（ESLint で強制）
│  │  ├─ types.ts            エンティティの型（サーバー内部の完全な形）
│  │  ├─ dto.ts              クライアントへ渡す形（秘密フィールドを Omit ＋ 許可リストで落とす）
│  │  ├─ plans.ts            プラン定義と利用判定
│  │  ├─ points.ts           ポイントのルール・付与判定・連続記録
│  │  ├─ authorization.ts    認可の判定（4ロール × リソース）
│  │  ├─ scoring.ts          クイズ・診断の採点
│  │  ├─ schedule.ts         クラス開催日（第n週の◯曜）
│  │  ├─ members.ts          退会の方針
│  │  ├─ jst.ts              JST の暦（今日・今月）
│  │  └─ schemas.ts          Zod スキーマ（クライアントとサーバーで共有）
│  ├─ data/
│  │  ├─ data-store.ts       DataStore インターフェース
│  │  ├─ index.ts            mock / supabase の切り替え
│  │  ├─ mock/               インメモリ実装（デモモード）
│  │  └─ seed/               empty（既定）/ sample（IPPO_SEED=sample）
│  ├─ server/
│  │  ├─ env.ts              デモモード判定・seed 種別
│  │  ├─ logger.ts           機密を伏せるロガー
│  │  ├─ services/           ドメイン＋DataStore を束ねる。認可ガードを必ず通す
│  │  └─ actions/            "use server"（Phase 2〜）
│  ├─ app/                   画面（Server Component が既定）
│  ├─ components/            表示のみ（data 層を import できない。ESLint で強制）
│  └─ proxy.ts               ルート単位の入口（Phase 2）
├─ supabase/migrations/      テーブル・RLS（Phase 6）
├─ e2e/                      Playwright（Phase 2〜）
└─ test/                     テスト用の補助
```
