# 06. ブラウザ自動操作（Claude in Chrome）

このアプリは、Claude in Chrome などのブラウザ自動操作から**人と同じ操作ができる**ことを運用要件にしている。
この文書は、その規約と、主要タスクの手順書。

> **現状**: ログイン・クラス動画・講義の手順は実装済みで、E2E（`e2e/`）に同じ手順を写してある。それ以外の画面は Phase 4〜5 で実装する。
> 各手順の「状態」欄が「実装済み」になるまでは、手順どおりに操作できない。

## 規約

### 要素の指し方

| 対象 | 規約 | 例 |
|---|---|---|
| 操作対象（ボタン・リンク・入力・行） | `data-testid="領域-対象-動作"` | `admin-user-add`、`admin-user-delete`、`coach-note-reply` |
| 一覧の行 | 行に `data-testid="…-row"`、行の中のボタンは同じ testid。行は表示名などの**見える文字**で絞る | `[data-testid="admin-user-row"]:has-text("ヒカル（サンプル）") [data-testid="admin-user-delete"]` |
| 画面 | `<main data-page="admin-users">` | 「いまどの画面か」を DOM だけで判定できる |
| 同じ文言のボタンが複数 | 親に `data-role="coach"` などの識別子 | `[data-role="coach"] button:has-text("えらぶ")` |
| アイコンだけのボタン | 必ず `aria-label` | `aria-label="メニューを開く"` |
| role + アクセシブルネーム | 画面内で一意にする | 「コーチ」ボタンが複数並ぶ画面を作らない |

- `data-testid` に**個人情報や ID を入れない**（`admin-user-delete-山田太郎` や `admin-user-delete-u-student-0001` は不可）。行の特定は見える文字で行う。
- 署名URL・`playbackId`・`storageKey` は DOM に出さない（POST のレスポンスでだけ受け取る）。

### ダイアログ

- `window.alert` / `confirm` / `prompt` は使わない（ESLint で禁止）。自動操作が固まるため。
- 確認は Radix `AlertDialog`（`role="alertdialog"`、`data-testid="…-confirm-dialog"`）。
- 肯定ボタンの文言は画面内の他のボタンと重ねない（「削除」ではなく「この会員を削除する」）。

### 状態は URL に

- タブ・フィルタ・ページはクエリ（`?tab=mentality`、`?page=2`）。直リンクで任意の状態を再現できる。
- 無限スクロールは作らない。「次へ」ボタン（`data-testid="pagination-next"`）と `?page=`。
- 不正なクエリ（`?page=abc`）は 1 ページ目に戻す（`listQuerySchema`）。

### 非同期の完了を DOM で観測する

| 状態 | 出し方 |
|---|---|
| 主要コンテナの読み込み | `data-state="loading" \| "ready" \| "error"` |
| 成功の通知 | トースト `role="status"`（例「追加しました」） |
| エラー | `role="alert"`。フィールドのエラーは入力の直後にテキストで出し、`aria-describedby` で結ぶ |
| 送信中 | ボタンを `disabled`、`data-busy="true"` |

### バックグラウンドタブで固まらない

- 各画面の主要コンテンツは**初回 HTML に含める**。骨格を Suspense のストリーミング頼みにしない（非表示タブでは `requestAnimationFrame` が止まり、Suspense の表示切り替えが走らないことがある）。
- どうしてもストリーミングする部分は、`setTimeout` による強制表示のフォールバックを持たせる。
- E2E に非表示タブでの検証を1本入れる（Phase 2）。

### フォーム

- すべての入力に `id` と `<label for>`。
- エラーはブラウザ標準の吹き出しに頼らず DOM のテキストで出す（`noValidate` を付け、Zod のメッセージを表示）。
- ファイル入力は `<input type="file">` を DOM に残す。見た目を整えるときも `display:none` にせず `sr-only` か `opacity-0`。

### 自動操作の入口（デモモードだけ）

- `/login` にロール別ワンクリックログイン: `demo-login-student` / `demo-login-guardian` / `demo-login-coach` / `demo-login-admin`（`IPPO_SEED=empty` では運営だけ出る）
- `IPPO_SEED=sample` で毎回同じサンプルデータ。
- デモデータの初期化ボタン `demo-reset`（`/login` に出す。デモモードだけ）。
- 本番モード（`isDemoMode() === false`）ではどれも出さない。

## 手順書

凡例: `#id` は入力欄、`[data-testid=…]` はボタンなど。成功判定は必ず `[role="status"]` の文言で行う。

### ログインする（デモモード）
状態: 実装済み
1. `/login` を開く（最初の状態に戻したいときは `[data-testid="demo-reset"]` をクリック）
2. `[data-testid="demo-login-student"]` をクリック（ほかは `demo-login-guardian` / `demo-login-coach` / `demo-login-admin`）
3. `main[data-page="student-home"]` が出れば成功（保護者 `guardian-home`、コーチ `coach-home`、運営 `admin-home`）
4. ログアウトは `[data-testid="header-sign-out"]`

### ログインする（本番モード）
状態: 実装済み。パスワードは利用者本人が入力する（自動操作では入れない）
1. `/login` を開く
2. `#loginId` にメールアドレス（運営・保護者）かログインID（生徒 `ippo-######`）、`#password` にパスワード
3. `[data-testid="login-submit"]` をクリック
4. 成功判定はロールごとの `main[data-page=…]`（上と同じ）。失敗は `[role="alert"]`（どこが違うかは出さない）

### 最初の運営アカウントを作る
状態: 実装済み。運営が1人もいないときだけ
1. `/setup` を開く。`[data-testid="setup-closed"]` が出たら、もう作成済み
2. `#displayName` と `#email` を入れ、パスワードは本人が入れる
3. `[data-testid="setup-submit"]` → `main[data-page="admin-home"]`

### 入会を申し込む（保護者）
状態: 実装済み
1. `/register` を開く（`main[data-page="register"]`。デモモードでは `[data-testid="register-demo-warning"]` が出る）
2. フォーム `[data-testid="register-form"]` に保護者の名前・メール、お子さまの名前・呼び名・学年・都道府県を入れ、同意にチェック
3. `[data-testid="register-submit"]` → `[data-testid="register-done"]`

### 申し込みを承認・却下する（運営）
状態: 実装済み
1. `/admin/applications` を開く（`main[data-page="admin-applications"]`）。無ければ `[data-testid="admin-applications-empty"]`
2. `[data-testid="admin-application-row"]` ごとに `[data-testid="admin-application-plan"]` でプランを選び、`[data-testid="admin-application-approve"]`
3. 承認すると招待リンクが1回だけ表示される。そのまま保護者に渡す（再表示はできない）
4. 却下は `[data-testid="admin-application-reject"]` → ダイアログ `[data-testid="admin-application-reject-dialog"]` の `[data-testid="admin-application-reject-confirm"]`
5. 既存会員へのログイン用リンクは `/admin/users` の `[data-testid="admin-user-issue-login"]`

### 招待リンクからパスワードを決める（保護者）
状態: 実装済み。パスワードは本人が入力する
1. 招待リンク `/invite/…` を開く（`main[data-page="invite"]`）
2. `[data-testid="invite-form"]` でパスワードを決め、`[data-testid="invite-submit"]`
3. `[data-testid="invite-done"]` にログインID（`[data-testid="invite-login-id"]`）が出る。`[data-testid="invite-go-home"]` で開始

### 運営として会員画面を確かめる
状態: 実装済み
1. 運営でログインし、ヘッダーの `[data-testid="nav-admin-member-view"]`（会員画面）をクリック
2. `main[data-page="student-home"]` と `[data-testid="admin-preview-bar"]` が出れば成功
3. 動画・講義へは `[data-testid="admin-preview-videos"]` / `[data-testid="admin-preview-lectures"]`、戻るときは `[data-testid="admin-preview-back"]`
4. 運営の閲覧では「見おわった」・ポイント・クイズの記録はつかない（ボタン自体が出ない）

### クラス動画を見る
状態: 実装済み
1. 生徒でログインし、`/videos?tab=mentality` を開く（タブは `soccer_iq` / `mentality` / `fitness` / `other`、無しで「すべて」）
2. `[data-testid="video-card"]:has-text("動画のタイトル")` をクリック
3. `main[data-page="video-detail"]` になったら `[data-testid="video-play"]` をクリック
4. `[data-testid="video-player"][data-state="ready"]` になるまで待つ
5. 動画の長さの 8 割が経ったら `[data-testid="video-complete"]` をクリック
6. `[role="status"][data-testid="video-complete-result"]` に「見おわったね！」が出れば成功（早すぎると「もう少し見てみよう」）

### 講義を読んでクイズに答える
状態: 実装済み
1. 生徒でログインし、`/lectures?tab=lc-mind` を開く
2. `[data-testid="lecture-card"]:has-text("講義のタイトル")` をクリック
3. `[data-testid="lecture-progress"][data-state="ready"]` になるまで待つ（読みはじめの記録）
4. 各 `[data-testid="quiz-question"]` の中のラジオボタン（`#quiz-q1-c1` など、ラベルつき）を1つずつ選ぶ
5. `[data-testid="quiz-submit"]` をクリック
6. `[role="status"][data-testid="quiz-result"]` に「◯問中◯問せいかい」が出れば成功
7. 表示された時間が経ったら `[data-testid="lecture-complete"]` をクリックし、`[data-testid="lecture-complete-result"]` に「読みおわったね！」

### 会員を追加する
状態: 実装済み（e2e/admin-users.spec.ts）
1. 運営でログインし、`/admin/users?tab=members` を開く
2. `[data-testid="admin-user-add"]` をクリック（URL に `new=1` が付き、フォームが開く）
3. `#displayName` / `#fullName` / `#email` を埋め、`#role` を選ぶ。生徒なら `#planCode` も選ぶ（`#ageBand` は任意）
4. `[data-testid="admin-user-submit"]`（文言「この内容で会員を追加する」）をクリック
5. `[role="status"][data-testid="admin-user-form-result"]` に「追加しました」が出れば成功。入力の誤りは各欄の下（`#displayName-error` など）に文字で出る。サーバー側の理由（メールアドレスが使われている、など）は `[data-testid="admin-user-form-result"]` に出る

### 会員を削除する
状態: Phase 5 で実装
1. `/admin/users?tab=members` を開く
2. 対象の行 `[data-testid="admin-user-row"]:has-text("表示名")` の `[data-testid="admin-user-delete"]` をクリック
3. `[role="alertdialog"][data-testid="admin-user-delete-confirm-dialog"]` が開く
4. `#confirmDisplayName` に表示名をそのまま入力
5. `[data-testid="admin-user-delete-confirm"]`（文言「この会員を削除する」）をクリック
6. `[role="status"]` に「削除しました」が出れば成功

### プランを割り当てる
状態: 実装済み（e2e/admin-users.spec.ts）
1. 運営でログインし、`/admin/users?tab=student` を開く
2. 対象の行 `[data-testid="admin-user-row"]:has-text("表示名")` の中の `[data-testid="admin-user-plan-select"]` でプランを選ぶ（「なし（未加入）」で割り当て解除）
3. 同じ行の `[data-testid="admin-user-plan-submit"]`（文言「プランを変える」）をクリック
4. 同じ行の `[role="status"]` に「プランを変更しました」が出れば成功

### クラス動画を登録する（アプリ内アップロード）
状態: Phase 5 で実装
1. `/admin/videos?tab=new` を開く
2. `#source` で「アプリ内アップロード」を選ぶ
3. `#title` / `#description` / `#category` / `#durationSeconds` を埋める
4. `#videoFile`（`<input type="file">`）にファイルを渡す
5. アップロード完了で `[data-testid="admin-video-upload"][data-state="ready"]` になるまで待つ
6. `[data-testid="admin-video-submit"]` をクリック
7. `[role="status"]` に「動画を登録しました」が出れば成功

### クラス動画を登録する（Mux）
状態: Phase 5 で実装
1. `/admin/videos?tab=new` を開く
2. `#source` で「Mux」を選ぶ
3. `#title` / `#description` / `#category` / `#durationSeconds` / `#muxPlaybackId` を埋める
4. `[data-testid="admin-video-submit"]` をクリック
5. `[role="status"]` に「動画を登録しました」が出れば成功

### クラス動画を登録する（YouTube）
状態: Phase 5 で実装
1. `/admin/videos?tab=new` を開く
2. `#source` で「YouTube」を選ぶ
3. 赤字の注意「この動画はアプリの外でも見られます」（`[data-testid="admin-video-youtube-warning"]`）が出ていることを確かめる
4. `#title` / `#description` / `#category` / `#durationSeconds` / `#youtubeId`（URL の `v=` のあとの11文字）を埋める
5. `#acknowledgedPublicExposure`（チェックボックス）をオンにする
6. `[data-testid="admin-video-submit"]` をクリック
7. `[role="status"]` に「動画を登録しました」が出れば成功

### サッカーノートに返信する
状態: Phase 4 で実装
1. コーチでログインし、`/coach/notes?tab=waiting` を開く
2. 対象の行 `[data-testid="coach-note-row"]:has-text("表示名")` の `[data-testid="coach-note-open"]` をクリック
3. `#reply` に返信を入力
4. `[data-testid="coach-note-reply"]` をクリック
5. `[role="status"]` に「返信しました」が出れば成功

### 動画レビューに返信する
状態: Phase 4 で実装
1. コーチでログインし、`/coach/video-reviews?tab=waiting` を開く
2. 対象の行 `[data-testid="coach-video-review-row"]:has-text("表示名")` の `[data-testid="coach-video-review-open"]` をクリック
3. `#reply` に返信を入力
4. `[data-testid="coach-video-review-reply"]` をクリック
5. `[role="status"]` に「返信しました」が出れば成功

### 出欠を記録する
状態: Phase 4 で実装
1. コーチでログインし、`/coach/sessions` を開く
2. 対象の開催回の `[data-testid="coach-session-open"]` をクリック（`/coach/sessions/[sessionId]` に移る）
3. 各行 `[data-testid="coach-attendance-row"]:has-text("表示名")` の中の `select[data-testid="coach-attendance-status"]`（id は `attendance-status-{行番号}`、ラベルつき）を選ぶ
4. `[data-testid="coach-attendance-submit"]` をクリック
5. `[role="status"]` に「出欠を記録しました」が出れば成功

### お知らせを投稿する
状態: Phase 5 で実装
1. `/admin/announcements?tab=new` を開く
2. `#title` / `#body` を埋め、`#audience` で対象（全員・生徒・保護者・コーチ）を選ぶ
3. `[data-testid="admin-announcement-submit"]` をクリック
4. `[role="status"]` に「お知らせを投稿しました」が出れば成功

> 出欠の select の id は行番号でつける（生徒 ID を入れない）。行の特定は表示名で行う。
